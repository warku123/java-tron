# Serving Index：差分页与页目录（本地实现说明）

## 范围

本次调整 Serving Index 的高度分页、跨页定位与目录时机，并合入 Blade 的批次简化。
不修改 History 正文、Chainbase key 身份、INLINE 门槛、查询上界或水位发布语义。

<https://troneco.atlassian.net/wiki/spaces/javatronx/pages/2604826647/Serving+Index+Geth>。

## 压缩页

所有整数头字段使用大端序；变长整数使用标准无符号 base-128 编码。
高度限制在 `[0, Long.MAX_VALUE]`，因此合法 varint 最多 9 字节。

| 字段 | 字节数 | 含义 |
| --- | ---: | --- |
| pageFormat | 1 | `1` |
| count | 4 | 本页条数，1～4097（由字节预算推导，见下） |
| restartInterval | 2 | 写入时的段长，默认 256；读端从文件读取 |
| segmentData | 变长 | 每段首条完整高度，后续条目为严格正差值，均为 Uvarint |
| restartOffsets | 2 × segmentCount | 尾部偏移表，相对段数据区的字节偏移，首项为 0 |

**页按字节滚动，不按条数**：追加前检查 `dataBytes + 8 > 4096`，对齐 Geth
无 extension 的 `estimateFull`。已有 4088 B 时仍可追加；Java 非负 `long` 的
Uvarint 最多 9 B，最后一条可把数据区推到 4097 B。4096 B 是高度数据区的滚动预算，
不含页头、restart 表和 CRC，不是完整页 value 的上限。每条至少 1 B，故条数上界 4097；
连续高度时一页可容纳数千条（起点 101 的连续高度实测 4074 条），大差值时少于此。
段数不单独存储，由头部推导：`ceil(count / restartInterval)`；
不要求页条数与 restart 段长整除，页的最后一段允许不满，新页重新开段。
偏移表放在页尾（对齐 Geth 块尾 restart 表），使追加只需拼接字节、不必移动旧数据；
`CRC32C:4` 覆盖以上全部字段并位于最末。4097B 数据区远小于 65536B，2B 偏移足够。
全量解码检查段长、偏移、段内条数、无尾随、规范 varint、加法溢出及全页严格递增。
直接替换现有 `encodeEpochPage` / `decodeEpochPage` 的编码，不保留旧定长页的生产
编解码分支或并行压缩页接口。页首 `pageFormat=1` 是记录布局标记，不是 descriptor
版本升级；旧定长页首字节为 0，读端拒绝该布局。保留旧页 golden 样本作为拒绝测试，
descriptor、coverage、原有 KeyMeta 和 key 的 golden 字节保持不变。

查询采用 Geth `seekGT` 的策略：以段首绝对高度为锚点二分（每步就地解码一个 varint），
只顺序扫描目标段，不再整页解码为 `long[]`。目标页在一次点查内只做一次 CRC 校验和
页头/偏移解析：条数、首/末高度一致性校验与后继查找共用同一个已校验页视图，
不对同一份字节重复校验四次。不声称减少物理磁盘 IO；KV get 数量与物理 IO 不等价。

## 跨页目录

目录使用新的数据库 key 前缀 `0x06`：

```text
06 || storeId:u16 || escapedRawKey || 00 00
```

value 为 `[format:1=1][pageCount:4][描述符 ×N][CRC32C:4]`，对齐 Geth 的
`indexBlockDesc`：每页定长 14B = `pageMax:8 + pageEntries:2 + pageId:4`。
页最大高度直接定长读取，无需 varint 解码；条数与页号参与一致性校验
（页号连续、条数在字节推导界内、最大高度严格递增）。
**每个分页 key 从第一页起就有目录**：字节分页后页数与尾页条数无法从
KeyMeta 总条数推导，描述符是唯一可信来源（对应 Geth 常驻内存的 descList）。
解码校验全部描述符条数之和等于 KeyMeta.count、末页 max 等于 KeyMeta.last。

目录最多一条记录/key，读写开销随页数线性增长；没有引入全局缓存。
页按字节滚动后单页容纳的条数远多于固定 512 条方案，页数与目录体积相应下降；
极热 key 的目录体积、整体读写放大是后续基准重点，不宣称解决了无界目录增长。

KeyMeta 保持原有字段结构，模式语义调整为：

- `1 = INLINE`：≤4 条，不变。
- `2 = PAGED`：历史值，新实现不再生成；无目录的页二分查询分支已删除，
  遇到该模式报错而非静默回退。
- `3 = PAGED_DIRECTORY`：分页 key 一律使用；目录必须存在，缺失或损坏报错。

查询在目录中按 `max` 二分找第一个 `max > target` 的页，只读取该目标页；
再检查目标页条数（对照描述符 entries）、末条及前页边界与目录一致，
最后返回 `(target, upperBound]` 的首个变化。
目标等于页最大高度时必须继续找后页。

## 追加、迁移与崩溃恢复

新写页一律使用压缩格式，统一走单次提交内的 `PageWriter`：逐条追加前检查
字节预算，满了就 finish 当前页、页号 +1 开新页。旧尾页即使已满也会读取并校验，
但不会改写；未满尾页由 `PageWriter(encoded, descriptor)` 重开——只解析页头、CRC 与
restart 偏移，不解码旧高度字节，原样保留数据前缀，只拼接新高度的差分 varint
（差值基准取描述符 max，等价 Geth 内存 desc.max），段满时追加 restart 锚点，
重算 CRC 后整条写回。页头 count 会更新，因此"value 前缀逐字节不变"只对
数据区成立，不对含 count 的页头成立。追加路径信任原子组提交的
KeyMeta 与描述符（Geth 同样信任 desc），旧页内容校验由 CRC、头部条数比对、
查询边界校验与统计扫描承担。

**分页边界与提交批量无关**：滚动判断只依赖已编码字节数，同一批高度无论
一次写入还是拆成任意多次提交，最终每页字节与描述符一致（有专项测试）。
目录更新：解码旧目录→重开尾页描述符被新描述符替换→按需追加新页描述符→
整条重编码写回（定长描述符复制，无变长重算）。

默认每次从 History 读取最多 1000 块，按 32 MiB 选择读取窗口；第一块即使超出也会读取。
读取窗口只约束输入：窗口内的完整块按 Geth `batchIndexer` 的形态累计进一张跨窗口的
`(store, rawKey) → 有序高度` 内存表（真实变更条数计 `pending`），到达变更条数阈值
（`flushChanges`，默认 8M，对齐 Geth `historyIndexBatch`）或本轮追赶目标即封存落盘；
块边界不再单独发布进度。与 Geth 对齐的是「按已解码的变更构建索引、不按 key 长度
猜输出、一个热 key 的一次 flush 只打开一次」；Geth 内部按 8M 条真实变更和已构建
batch 的实际大小分次落盘，我们的分批写按已编码 mutation 字节（`dataBatchBytes`）切分
key 原子子批：整体不超预算的 flush 仍是一次原子写；超过时先写一条 flush intent，
再写各数据子批，最后一个同步批发布 coverage 与进度并删除 intent。中断后重开时按
intent 从 History 重放同一区间：仍处旧进度的 key 正常追加，已写完的 key 与重放结果
逐高度核验一致后跳过，恢复自身可再次中断并幂等重试；查询始终以旧 I 为上界
（覆盖守卫在读取页之前拒绝超出 I 的查询）。

正式提交按聚合后的 key 读取 KeyMeta，分页 key 再读目录和尾页。不同 key 由有界 worker
并行准备（`tron.archive.serving.buildThreads`，默认 1 即原串行路径）：worker 从共享游标
动态领取下一个 key，只读 KeyMeta／目录／尾页并产出该 key 的完整 mutation 组，同一 key
的全部高度仍在单个 worker 上按序追加；完成顺序即交付顺序，慢 key 不阻塞已完成的 key，
构建线程把收到的 key 原子组按 `dataBatchBytes` 合批写库，最终索引与串行构建一致。
不超预算的 flush 仍一次同步原子提交索引数据、coverage 和进度；超过预算的流式路径见
上节。worker 或写入失败即停止派发，等待在途读取退出后向上传播；已落盘的数据子批由
重开后的 intent 恢复处理。不再写新的 SOLO 分块。旧 SOLO 仍按 KeyMeta.last 做 R-IDEM，
目录模式重放时还会校验目录。原生 snapshot 固定目录、页及读取上界，`I+1` 残留仍不可见。
与 Geth 对齐的是无 extension 分页、Uvarint/restart 编码、后继查找策略和按 key 派活的
并发形态，不是落盘格式、批次、进度发布或恢复机制。

按与 Blade 确认的实施口径，保留 `VERSION=4`、`EXACT_VERSION=5`，不新增 descriptor
版本，不增加多版本分类函数，也不增加打开时升级 descriptor 的维护写入。
原有 v3/v4 路径不变；exact-v5 的页编码直接由本实现替换。

**版本号相同不等于页编码兼容。** 现有含定长页的索引不能直接沿用；打开时的原有
descriptor/coverage 检查不扫描全部页，因此可能先打开成功、访问旧页时才失败。
只含 INLINE 的旧 key 也不能据此证明整个旧库可复用；不支持在旧库上直接滚动追加。
旧程序同样不能直接使用本实现写出的压缩页及目录模式。本次不提供自动迁移、
自动删库或新的重建触发逻辑，不把页解码失败描述为可靠的全库部署前置检查。

## 后续事项：目录写放大与物化滞后（本次不实现）

尾页追加已对齐 Geth 零解码拼接，写放大剩余项是目录：虽然逻辑上只更新尾页
描述符，但 KV 接口仍写回完整目录 value（定长 14B×页数），
极热 key 随页数线性增长；落盘本身因 value 不可变＋CRC 仍为整条写回。

候选方向是“物化滞后”：每个 key 至多一条尾增量记录（差分 Uvarint＋CRC），
追加先合并进增量记录；低于阈值时只写增量与 KeyMeta（同一原子组），
达到阈值或跨过页边界才物化整页、清理增量并更新目录。查询读取最后一页时
需要合并增量记录；崩溃恢复沿用 R-IDEM，不改变重放语义。

该方向属于格式扩展：需新增记录前缀与尾增量编解码，并调整目录末项校验
（末项为物化最大高度，需新增与 KeyMeta.last 的一致性不变量）、
统计扫描、重放校验与预算路径。阈值选取依赖真实基准：热 key 追加频率、
页大小分布、增量阈值与物化成本的对照均未测量，先基准后实施。

## 不实施项：INLINE 差分编码

INLINE（≤4 条）高度保持定长 8B/条，不改差分 Uvarint。评估结论：

- 收益小且落在冷 key 上：差分每 key 仅省约 25B，INLINE 装的恰是变化次数
  极少的 key，索引体积大头在页与目录，不在冷 key 元数据；
- 代价是破坏 KeyMeta 字节布局：与“原有 KeyMeta golden 字节保持不变”的
  既定口径冲突，长度推导与校验需重做，得不偿失；
- Geth 没有 INLINE 层（其索引只有 descList＋块两级），保留定长不属于
  对齐欠账；INLINE 4 条顺序解码即可，页级追加与段锚点函数不适用。

底层 varint 原语（writeUvarint/readUvarint/addDelta）本就可复用，无额外
改造成本；若将来 KeyMeta 因其他原因演进格式，INLINE 差分可同批重新评估。

## 验证口径与限制

新增 codec 测试覆盖 1/64/256 段长、跨段边界、Long.MAX_VALUE、旧定长页拒绝、
损坏/截断/非法偏移/非规范 varint/零差值/溢出、超预算整页拒绝、
头部条数与数据长度越界拒绝、重开尾页（含条数不匹配拒绝、字节等价重开、
数据前缀复用）及段锚点二分查询。
字节滚动专项：1B/条与 5B/差值两种序列得到不同的页条数（4089/819），
证明分页由字节而非条数驱动；默认段长下起点 101 的连续高度首页为 4074 条，
该页完整 value 大于 4096 B。另测 `4088 + 9 = 4097 B` 的数据区边界。
批量无关性在 codec 层与 Store 层双重验证：6000 条随机高度单趟分页 vs
随机分块逐次重开尾页，页字节逐一相等；整库一次性提交 5000 块 vs
100×50 块分批提交，页/目录/KeyMeta 字节逐一相等。
目录集成测试覆盖第一页即有目录、字节滚动跨页、满页尾追加不改写旧页、
旧 snapshot、目录缺失拒绝查询、SOLO 重放及已写残留组目录缺失时拒绝重放；
检查 descriptor 保持 5 且重开不改写进度记录。
保留既有 Serving Index 测试并复跑；具体执行结果以本次交付说明为准。

合成夹具：512 条连续高度、起点 84000000、段长 256 的页为 533B；
4089 条连续高度（段长等于预算、单段）数据区 4089B、完整页 4102B。
这些只是编码字节夹具，不是实际数据库或全索引节省。
wiki 的 33.66% 估算未计本实现所有新增字段和目录，不能作为实现后测量结果。

实际数据库大小和 compaction 成本仍待后续基准；本次未访问或修改远端样本。
